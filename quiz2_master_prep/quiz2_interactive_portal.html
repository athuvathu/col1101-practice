A binary min-heap is an Almost Complete Binary Tree (ACBT) satisfying $A[\lfloor (i-1)/2 \rfloor] \le A[i]$. Use this sandbox to visualize tree nodes and 0-indexed array mapping.

Key Theoretical Guarantees (Lectures 19–21)

1. Ancestor Rank Theorem

Every node at depth $d$ has strictly $d$ ancestors on its path to the root. In a min-heap with distinct elements, all $d$ ancestors are strictly smaller than itself:

$$\text{rank}(v) \ge \text{depth}(v) + 1$$

• 1st smallest (minimum): Exclusively at depth 0 (index 0).
• 2nd smallest: Exclusively at depth 1 (indices 1, 2).
• 3rd smallest: Depths 1 or 2 (indices 1 to 6). Never depth ≥ 3!
• 4th smallest: Depths 1, 2, or 3 (indices 1 to 14). Never depth ≥ 4!

2. Why Fast Build Heap is $\Theta(n)$ Linear

Bottom-up sift-down does work proportional to height (distance to leaf). The $\approx n/2$ leaves do 0 work! Summing work across heights yields:

T(n) ≤ n * ∑_{h=1}^∞ (h / 2^h) = n * 2 = Θ(n)

Deadlock: Reverse Lock Acquisition Trace

# Thread 1:                     # Thread 2:
with lock1:                     with lock2:
    with lock2:                     with lock1:
        transfer()                      transfer()

• At $t_0$: Thread 1 acquires lock1.
• At $t_1$: Thread 2 acquires lock2.
• At $t_2$: Thread 1 requests lock2 → BLOCKS (held by Thread 2).
• At $t_3$: Thread 2 requests lock1 → BLOCKS (held by Thread 1).
• Outcome: Circular wait! Both threads sleep forever.

The Fix: Global Lock Ordering (Havender's Rule)

Force all threads to acquire locks in strictly increasing order based on a global ID:

first, second = (lock1, lock2) if id(lock1) < id(lock2) else (lock2, lock1)
with first:
    with second:
        transfer()
